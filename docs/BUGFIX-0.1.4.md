# 0.1.4：有限自动重试与结果/日志分离

目标版本：`0.1.4`（测试版）。本文描述本次变更及验收边界，不代表旧插件已自动升级，也不声明尚未执行的回归已通过。

## 问题与本次选择

旧任务可能在中断后停于 `needs_review`，页面刷新又使分享弹窗消失，恢复路径仍依赖逐项核对链接和密码，因而不能直接继续。

用户已明确取消逐项人工核对，并允许对未完成项重复分享。0.1.4 移除现行逐项核对、填写历史密码与批准入口；旧 `needs_review` 不再要求原弹窗存在或人工采用历史链接。旧版操作仅留在原历史文档中，不适用于当前版本。

## 新的执行规则

- 本机原任务中已持久化的 `done` 项跳过，继续原快照的剩余未完成项。
- 中断、链接改变、密码不确定或弹窗消失时，允许重新执行该项分享流程；网站可能复用或生成链接。
- 每项每轮最多自动尝试 3 次，首次计入上限；仍失败保存为 `failed` 并继续下一项，不无限重试。
- “仅重试失败项”为失败项开始新一轮有限尝试，保留之前的失败、尝试和历史 URL，不重做成功项。
- 只在本次同一分享弹窗内确认准确项目、合法 URL 和启用的有效密码后保存成功；不关闭再重开验证。
- 旧观察密码或导入密码可能已失效，不能直接视为当前有效；重试允许重新分享或设置密码，不保证旧密码不变。

历史链接单独记录到日志和完整进度中。它们可能仍有效，也可能未受密码保护；插件不保证撤销旧分享，不把成功的新结果当成旧分享已被清理的证明。

## 不变的停止边界

以下情况仍须停止整个任务，不能耗尽单项次数后当作普通失败继续：

- 账号或目录变化，或已识别账号无法确认一致。
- 验证码/CAPTCHA、限流，或需要绕过网站限制才能继续。
- 目标项目歧义、错误项目/弹窗或无法可靠识别操作对象。
- 存储失败、缺少持久化 ACK、stale run、失效的 tab/document 绑定或 revision 冲突。

未知账号跨 document 恢复时，可一次确认仍为原账号；这是本次恢复的身份确认，不是逐项分享核对，不能覆盖已知账号不一致。任何后续远端变更都必须先通过上下文检查和所需 checkpoint ACK。

## 两种 TXT 与独立导出

**结果 TXT** 使用 UTF-8 BOM、Windows CRLF，只包含成功项，每项一行，以下为虚构示例：

```text
1.链接：https://share.weiyun.com/EXAMPLE 密码：abcd
```

不含标题、名称、有效期、统计、失败或未完成占位。使用原快照 `ordinal`，不压缩编号；例如第 2 项失败时，成功项仍可为 `1.`、`3.`。没有成功项时不写占位内容。

**日志 TXT** 是另一份文件，包含统计、任务和项目状态、失败原因、尝试与重试、历史 URL 及验证边界。结果 TXT 不再混入这些诊断信息。

任务正常处理结束，包括有失败项的结束，自动下载结果 TXT 和日志 TXT。手动导出 TXT、日志、JSON 各自独立；下载失败可只重新导出对应文件，不重新分享。JSON 含完整进度与敏感链接、密码，应妥善保管。

## 原任务升级

1. 暂停并等待安全 checkpoint，先导出 JSON 备份，按需导出结果与日志。
2. 将 0.1.4 发布内容覆盖原来加载的同一个插件目录；不要卸载、清空 storage、更换 profile 或加载路径。
3. 在 `chrome://extensions`（Edge 为 `edge://extensions`）点击“重新加载”，确认版本为 `0.1.4`。
4. 刷新原微云 tab，回到原账号、原目录，点击工具栏插件图标读取原任务。
5. 点击“继续任务”；旧 `needs_review` 进入有限自动重试，`done` 跳过，无需逐项核对。账号未知且跨 document 时仅按提示确认原账号。

仅覆盖文件或重开面板不能更新旧 content script。已有本机任务不必为了升级重新导入；确需迁移时，外部 JSON/旧 checkpoint 只作为候选和历史来源，候选项重新分享，不直接信任文件中的完成状态或密码。

## Fixture 回归要求与验证边界

应覆盖刷新丢失弹窗后直接继续、旧 `needs_review` 与中断阶段恢复、已完成项跳过、单项有限重试成功/耗尽后继续、仅重试失败项，以及所有整批停止条件。还应检查原账号的一次确认、checkpoint ACK 和 stale-run/revision fence，防止新策略绕过旧有保护。

导出回归应覆盖结果 TXT 的 BOM/CRLF、精确行格式、仅成功项及保留 ordinal，日志中的统计/失败/重试/历史 URL，完成后的双文件下载、独立手动导出和下载失败不重做分享。外部导入必须重新执行候选分享。

本轮仅使用隔离的本地 fixture，不读取或写入真实云盘，不创建真实分享或修改真实密码，不声称真实 60 项 E2E 成功。上述是验收要求，不是测试通过数量；最终环境与结果以发布包 `TESTING.md` 为准。独立服务端持久化、接收端访问、分享复用及真实限流行为不由同一弹窗或 fixture 证明。
