# 0.1.2：绑定当前弹窗的人工采用（历史记录）

本文记录用户已提交至 `outputs/weiyun-batch-share` 的 0.1.2 构建行为，不代表 0.1.3 的当前自动流程。目标发布版本为 0.1.3，使用步骤以 [README](../README.md) 及 [BUGFIX-0.1.3.md](BUGFIX-0.1.3.md) 为准；[BUGFIX-0.1.1.md](BUGFIX-0.1.1.md) 保留原有历史内容。

## 问题与修复范围

早期自动路径在添加密码后关闭并重开分享弹窗，再依据回显判断密码。已出现人工处理并采用当前弹窗后，又走重开验证、回到同一项 `needs_review` 的问题。0.1.2 为人工采用增加 `manualReview`，将批准绑定到当前准确项目的受保护弹窗、链接和有效密码。

人工采用后先持久化批准，runner 优先处理该项，匹配批准与当前弹窗，再保存 `manual_review` 完成结果。该人工项不再调用 `openShare` / `addPassword`，完成持久化收到 ACK 后才关闭弹窗、处理剩余项目。存储失败停止后续变更，关闭失败保留已保存结果并暂停。

人工记录不是独立服务端或接收端验证，不能伪装为 `reopened_dialog`；原观察链接、候选及相关链接仍需保留和核对。目录、账号、项目、URL / 密码、任务 revision、页面身份及重复链接等保护没有因人工采用而取消。

## 0.1.2 仍存在的限制

- **正常自动流程仍会重开弹窗验证。** 不能把人工项不再重开理解为所有流程已经改为同一弹窗确认。
- **人工入口仍依赖当前弹窗。** `READ_REVIEW` 必须读到该项受保护弹窗；刷新或关闭弹窗后无法采用本地历史链接。
- 弹窗消失时会出现 `DIALOG_MISSING`，仅反复点击“采用当前弹窗链接并继续”不能恢复。该缺口不是目录列表 `0 / 60` 的问题。
- 旧版补码可能已改变历史密码。不能因重开后的输入为空就断言服务端密码丢失，也不能保证所有历史密码仍有效。
- 当前本机任务中的人工批准不应通过导入外部备份自动变成可信授权；导入仍属于候选核对。

0.1.3 才将既有 `manualReview` 改动同步回 TypeScript 源，去掉正常流程为了验证而重开弹窗，并增加 `reviewSource: saved_link` 的历史核对路径。此处不把这些后续行为追溯写成 0.1.2 已支持。

## 验证证据与边界

0.1.2 的历史交付记录包含对已交付 JavaScript 的隔离人工采用回归；不代表当时已重新执行完整 TypeScript 或真实微云端到端测试。本轮又在 isolated Edge fixture 稳定复现刷新后完全相同的 `READ_REVIEW` / `DIALOG_MISSING` 报错，并通过 0.1.3 修复后的历史链接路径转绿。

具体测试数量、环境及最终通过情况以发布包 `TESTING.md` 最终报告为准，不在此固定数量。本轮真实云盘没有写入、新分享或改密码，不声称真实 60 项端到端验收，也不承诺固定完成时间。

## 从 0.1.2 升级

1. 先导出进度 JSON 备份；运行中的任务先暂停并等待当前项保存完成。
2. 用 0.1.3 发布内容覆盖原来加载的同一个 extension 目录，不卸载、不清空 storage、不更换 profile，以保留 extension ID 与本地进度。
3. 在 `chrome://extensions` 或 `edge://extensions` 重新加载，确认版本为 `0.1.3`，然后刷新微云 tab 并点击工具栏图标读取原任务。
4. 弹窗已消失时选“页面已刷新 / 弹窗已关闭：核对历史链接”，打开本项已记录链接核对有效密码，手动填写并明确确认，只继续原任务，不重建。

历史密码可查看但可能已过期。确实不知道有效密码且历史值无效时，插件不能恢复，不应盲目重开分享或反复添加密码试错。
