# Implementation Notes

目标发布版本：`0.1.4`。本文规定本次实现与验收约束；不表示旧构建已自动升级，也不替代发布包的最终测试报告。历史版本行为仅见 [0.1.1](BUGFIX-0.1.1.md)、[0.1.2](BUGFIX-0.1.2.md)、[0.1.3](BUGFIX-0.1.3.md)，本次变更见 [BUGFIX-0.1.4.md](BUGFIX-0.1.4.md)。

## Runtime 与任务范围

- MV3 service worker 管理本地任务及串行 storage 更新，持久化成功后才返回 mutation ACK。
- isolated-world content script 执行 DOM 循环，以 task ID、run ID、tab ID 和随机 `documentNonce` 绑定 runner；Side Panel 仅为客户端，关闭面板不等于停止 runner。
- worker reload 不自动恢复旧 DOM 循环。恢复前确认旧 runner 已失效，重新绑定当前 document；旧执行器不得继续写入或操作页面。
- 快照只包含当前目录直接项目。adapter 滚动或翻页、去重，并核对明确总数后才开始分享；隐藏列表、数量不完整或项目身份歧义不能放行。
- 使用固定快照的 key 和 `ordinal`，恢复不重排编号；本机任务中已持久化的 `done` 项跳过。

## 自动分享与有限重试

用户已允许中断、链接或密码结果不确定时重复分享。0.1.4 不提供逐项人工核对或批准流程，也不以读取旧弹窗、手动输入历史密码为继续条件。

每项一次尝试沿用 `opening_share -> link_observed -> securing -> verifying -> done` 的正常阶段。失败后的下一次尝试重新执行该项分享流程，网站可能复用原链接，也可能生成新链接；不要求复用历史 URL，不承诺旧密码不变。

1. 每项在每个 run 内最多自动尝试 3 次，首次计入上限。记录各次失败和重试；程序不会自动开启新 run 来无限重试。
2. 可重试的单项错误包括分享中断、弹窗消失、链接改变、密码未显示或本次密码状态无法确认；先持久化已观察信息，再在预算内重试。
3. 达到上限仍失败时保存 `failed` 与最终原因，收到 ACK 后继续下一项；不能仅因存在失败项就终止剩余目录处理。
4. 用户主动“继续任务”或“仅重试失败项”会开启新 run，为参与本轮的未完成项提供新的 3 次预算。中断项恢复为 `pending`；`failed` 仅在 `retryFailed` 为 true 时重置为 `pending`，普通继续不重试失败项。保留此前失败、重试和历史链接记录，不重做 `done` 项。
5. 没有未完成项后，全部成功进入 `completed`，存在失败进入 `finished_with_errors`；两种正常结束都触发结果与日志自动下载。

`attempts` 累计记录历次实际尝试，供日志使用，不随新 run 清零，也不直接作为本轮 3 次上限的计数。当前 run 的单项预算单独计算；主动恢复可获得新预算，不等于程序自动无限重试。自动重试不得将安全停止错误改写成普通 `failed` 后继续。

## 同一弹窗确认

`confirmShare` 只等待和重读本次**同一分享弹窗**中的准确项目、合法 URL、密码启用状态及非空有效密码。当前弹窗能读取有效密码时使用本次值；需要设置密码时通过微云页面处理。历史 `observedPassword` 或导入候选密码不是当前有效性的证据，不能代替本次弹窗确认。

完成记录的 URL、密码必须与本次确认一致，密码通过格式校验，确认时间有效，并满足项目身份及结果唯一性校验，才能保存为 `done`。与另一已完成项出现相同 URL 时，按跨项目身份冲突停止整个任务，不导出可能属于错误项目的结果；这与用户允许同一未完成项目重复创建分享不同。明确的错误项目或身份歧义同样停止整个任务。

新自动结果使用 `verification: same_dialog`。保存完成结果并收到 ACK 后，才可为处理下一项关闭当前弹窗；**不为了验证而关闭、重开该项**。重试时重新进入分享流程是新的尝试，不是对已完成结果进行重开验证。

空白密码输入不证明服务端密码已丢失，也不证明历史密码仍有效。有限重试可重新设置密码或产生额外分享；用户已接受这一边界，不再等待逐项人工采用。

## 仍须整批停止的条件

| 条件 | 行为 |
| --- | --- |
| 原目录变化，或已识别账号不同/无法确认一致 | 停止，不对新上下文执行分享 |
| 验证码/CAPTCHA、限流 | 停止，不自动绕过或耗尽单项预算后继续 |
| 项目匹配歧义、错误项目/弹窗、无法可靠识别目标 | 停止，保留记录，不尝试其他可能的项目 |
| storage 写入失败、缺少持久化 ACK | 停止后续远端变更、重试及下一项 |
| stale run、失效的 tab/document 绑定或并发 runner 冲突 | 拒绝旧执行器，停止操作 |
| revision fence 或当前项目状态不匹配 | 拒绝过期提交，重新读取任务状态 |

错误分类优先于有限重试策略。同一个错误即使发生在普通分享阶段，只要属于上述安全条件就必须停止；不能对所有异常一律 catch 后继续。

账号未知且跨 document 恢复时，可一次确认仍为原账号。确认只绑定本次恢复上下文，不是对每项分享的批准，不可覆盖已识别的账号不一致，也不可取消目录、run、document 或 revision 检查。昵称不是稳定身份。

## 持久化与恢复边界

1. 点击分享入口前先保存尝试及 `opening_share`；修改密码前保存已观察 URL 与 `securing`，验证前保存本次密码及 `verifying`。
2. 新观察链接、旧候选 URL、错误携带 URL 及被替换的观察值应保留历史来源；必须在下一次可能产生外部变更的尝试前得到持久化 ACK。
3. 任务修改在串行 storage 操作内核对最新 run ID、revision、item key 与上下文；仅排队写入不替代 stale-run/revision fence。
4. `done` 及 `failed` 的结果必须先持久化，再推进下一项；持久化失败或 ACK 不确定时停止，不能继续创建分享。
5. 升级后主动继续时，旧 `needs_review`、没有 URL 的 `opening_share` 及其他中断未完成阶段恢复为 `pending`，保留 `restartRequired` 意图并优先重新分享。收到重试 checkpoint ACK 后仅关闭属于本项的旧弹窗，不直接采用旧批准。`failed` 仅在 `retryFailed` 为 true 时重置；已 `done` 的项目保持原记录并跳过，不追溯提升历史验证强度。
6. 原快照仍有待处理项时不能直接 `finish`；单项耗尽后记录 `failed` 并继续剩余项目。暂停在安全 checkpoint 生效；未耗尽项在暂停前恢复为待处理，不因暂停时序而被普通继续漏过。
7. `finished_with_errors` 没有普通续跑工作时拒绝 `RESUME`，只允许显式重试失败项，避免新建空 run 并重复下载。完成状态持久化后由后台独立排队结果/日志下载，不依赖 content script 再发一次消息；重新连接补发最新已结束任务缺失的自动导出。

这些保护不提供 DOM、网络与 storage 之间的 exactly-once 保证。远端变更后崩溃可能留下多个仍有效或密码未知的分享；本版本选择保留日志并在安全边界内有限重试，而非逐项等待人工核对。

## 导出与导入

### 结果 TXT

- UTF-8 BOM，每个成功项一行，以 Windows CRLF 换行；仅输出有已保存结果的 `done` 项。
- 精确行格式为 `{ordinal}.链接：{url} 密码：{password}`，使用原快照 `ordinal`，不重新连续编号。
- 不输出标题、名称、有效期、统计、验证说明、历史 URL 或未完成占位。零成功时不写占位内容。

虚构示例：

```text
1.链接：https://share.weiyun.com/EXAMPLE 密码：abcd
```

### 日志 TXT 与 JSON

- 日志 TXT 为独立文件，包含任务/项目统计与状态、失败原因、每轮尝试和重试、历史 URL，以及同一弹窗确认的验证边界。
- 历史链接带上项目和尝试来源，不能只保留最后一次覆盖值；列出 URL 不表示已撤销、已保护或已经访问验证。
- 历史结果的验证方式原样保留在日志/JSON，不将旧记录改写成更强的验证证明。结果 TXT 保持极简格式。
- `completed` 和 `finished_with_errors` 正常结束后，分别自动下载结果 TXT 与日志 TXT；手动导出 TXT、日志、JSON 是三个独立操作。
- 下载失败不回滚已保存结果，不重新分享；两份下载分别记录结果，允许独立重新导出失败的文件。
- JSON 保留完整进度及历史，含敏感 URL 和密码。继续本机原任务跳过 `done`；外部 JSON/旧 checkpoint 的完成状态与密码不作为可信成功证据，导入候选重新分享并在当前同一弹窗确认。
- 导入仍校验来源目录、可识别账号、字段格式和项目唯一匹配；允许重复分享不等于允许跨目录、跨账号或模糊匹配。

## Adapter、权限与隐私

既有列表 selector、滚动及完整采集回归继续保留。运行时 adapter 使用 DOM，不读取 cookie、token storage、网站内部应用状态或私有 API，不使用 MAIN-world injection。无稳定 ID 且无法区分同名/同元数据替换项时停止，不推断目标身份。

诊断只输出固定 allowlist 的 class token、attribute name 和结构计数，不输出任意 attribute value、文件名、分享链接、密码或登录凭据。历史 URL 日志是用户主动导出的敏感任务信息，不能混入结构诊断。

发布 manifest 权限为 `activeTab`、`scripting`、`storage`、`sidePanel`、`downloads`，无持久 host permissions。toolbar action 临时授权当前 tab；任务仅保存在 `chrome.storage.local`，不使用 `storage.sync` 或第三方后端。网页分享操作仍与微云通信。

测试 harness 使用独立 profile 与一次性 extension 副本，只为完全拦截的 fixture 添加临时 host permission；测试权限不能进入发布 manifest。本地数据不是加密保险箱，删除本地任务不撤销云盘分享。

## 升级与验收

升级顺序为：暂停并备份 JSON -> 覆盖原加载目录 -> reload extension 并确认 `0.1.4` -> 刷新微云 tab -> 回原账号、原目录 -> 继续原任务。仅重新打开面板不能更新旧 content script；不要卸载、清空 storage 或更换 profile/加载目录。未知账号跨 document 仅进行本次恢复所需的一次原账号确认。

以下为 fixture 回归要求，不是通过声明：

- 正常流程只在同一弹窗确认；完成项不为验证关闭重开，旧 `done` 不重做。
- 旧 `needs_review`、无 URL 的中断项、刷新后弹窗消失、旧密码不回显均可进入有限自动重试，无逐项人工核对 UI。
- 单项首试成功、后续尝试成功、同一 run 内耗尽 3 次成为 `failed` 后继续下一项；主动继续开启新 run 预算，中断项恢复为 `pending`，`failed` 仅在 `retryFailed` 为 true 时重置，累计 `attempts` 与历史 URL 不丢失。
- 账号/目录变化、验证码/限流、错误项目或匹配歧义、storage/ACK 失败、stale run、document/revision 冲突仍整批停止。
- 未知账号跨 document 一次确认后继续，确认不绕过可识别的账号冲突。
- 结果 TXT 的 BOM/CRLF、精确一行格式、仅成功项、原 ordinal 与零成功；日志完整性、两个独立自动下载、下载失败后独立导出。
- 外部导入不信任已完成状态或历史密码，候选重新分享；完整采集、lazy loading、隐藏列表排除与隐私诊断继续回归。

本轮仅 fixture，无真实云盘写入、新分享或密码修改；不声称真实 60 项 E2E 成功。具体执行环境及最终结果见发布包 `TESTING.md`，不固定测试数量。历史只读页面结构核对不能替代真实分享验收；服务端密码保存、接收端访问、分享复用、限流提示及真实安装链路仍需独立验证。

## Known Limits

- 创建链接和设置密码是分开的 UI 步骤，可能存在短暂无密码窗口。
- 有限重试可能产生额外分享或替换密码，不保证撤销旧链接、恢复未知密码或维持旧密码。
- DOM 显示只代表观察当时的同一弹窗状态，不证明服务端持久化或接收端持续可访问。
- document/browser 结束后不继续后台 DOM 操作；恢复需重新绑定正确上下文。
- 不提供并发分享弹窗、私有 API 加速、自动撤销分享、删除云盘文件或绕过 CAPTCHA/限流；不承诺真实批量耗时。
